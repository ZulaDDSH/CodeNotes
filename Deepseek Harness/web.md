# web code notes

`packages/web/web/src/safety.ts:readBoundedJson` (finding 332): every search and API provider reads JSON bodies, success and error alike, through this streaming reader. It rejects a declared `content-length` over the cap and cancels the stream as soon as the running total passes the cap, throwing `WEB_RESPONSE_TOO_LARGE` before any `JSON.parse`; the caller classifies a read failure against its own signal, so a cancellation during a bounded read stays `WEB_ABORTED`. An over-cap error body only costs the provider's detail message, never the HTTP error.

`packages/web/web/src/safety.ts:boundSearchResult` (finding 332): `WebRuntime.search` applies this to every provider result after the source-count cap, so answer text, titles, snippets, summaries and dates are cut to `WEB_SEARCH_FIELD_MAX_CHARS` with a trailing ellipsis (the same marker the tool uses for summaries), and a source whose URL exceeds `WEB_SEARCH_URL_MAX_CHARS` is dropped and sets `truncated` because a cut URL would be a different link. Bounding at the seam covers the model-facing text and the persisted tool meta together.

`packages/web/web/src/safety.ts:redactEndpoint` (finding 341): strips user information, query and fragment from an endpoint before it is recorded in a session event or placed in model-facing guidance; the request itself still uses the real URL. A secret embedded in a path segment cannot be recognised and is not removed.

`packages/web/web-search-exa/src/provider.ts:mapExaResult` (findings 334, 337): the adapter no longer sends Exa's deprecated, ignored `highlightsPerUrl` (the request asks `highlights: true`), and `highlightsPerResult` now bounds how many non-blank returned highlights are joined with ` … ` into `snippet`. A result with no highlight keeps its URL, title and date without a snippet, so URL-only results and an all-snippetless response are no longer reported as "No results found". Whether Exa returns more than one highlight per result by default is UNVERIFIED (no live request was made).

`packages/web/web-search-exa/src/provider.ts:ExaSearchProvider::search` (finding 333): cancellation is decided by the caller's signal (`signal.aborted`) as well as by a `DOMException` named `AbortError`, so a custom abort reason surfaces as `WEB_ABORTED` carrying `signal.reason` as `cause`; the same applies to the Perplexity and body-read paths, and `readBoundedJson` cancels its reader when the signal aborts so a stalled stream cannot outlive the cancellation.

`packages/web/web-search-perplexity/src/provider.ts:mapPerplexityResponse` (finding 336): structured `search_results[]` entries with a URL come first in their original order, then every `citations[]` URL not already present, deduplicated; an empty or incomplete structured list no longer hides citations. A `search_results` value that is present but not an array still fails as an unprocessable body.

`packages/web/web-search-deepseek/src/provider.ts:mapAnthropicResponse` (finding 335): a `web_search_tool_result` block whose content is an error object, is missing, or holds `*_error` items counts as a failed search. When no source arrives and any block failed the mapper throws `WEB_PROVIDER_ERROR` naming the error codes; a block with an empty content array is a verified empty search; when sources and failures coexist the result's `content` carries a note that the sources may be incomplete, which the tool renders before the source list.

`packages/web/web-search-deepseek/src/provider.ts:DeepSeekSearchProvider::search` (finding 341): the endpoint put in the `web/deepseek-search-llm-request` session event and in model-facing error guidance goes through `redactEndpoint`; the request is still sent to the unredacted URL. A base URL carrying a query string swallows the appended `/messages`, so its redacted endpoint shows the base without that suffix.

`packages/web/web-deepseek-api/src/transport.ts:searchEndpointError` (finding 341): the endpoint named in failure guidance is redacted with `redactEndpoint`.

`packages/web/web-deepseek-api/src/index.ts:Config` (finding 342): `sendOriginalQuestion` defaults to false, so the Search API receives only the model's own query unless an operator opts in to sending the 128-character prompt prefix as `ori_question`.

`packages/web/web-deepseek-api/src/fetch.ts:DeepSeekFetchApiProvider::fetch` (finding 343): the result carries no `statusCode` because the Fetch API reports neither the target's status nor a final URL; `WebFetchResult.statusCode` is optional, the tool header says the status and final URL were not reported, the tool output schema and card meta omit it, and the web fetch card (`packages/web/tool-web/src/fetch.ts:fetchMetaFromResult`, `packages/client/ui-tool/src/client/tool/models/web-card-model.ts:webCardModel`, `packages/client/ui-primitives/src/WebBlock.tsx:WebBlock`) accepts the absent status and renders no HTTP label instead of falling back to the generic card; a present but non-numeric status is still malformed.

`packages/web/web-fetch-http/src/provider.ts:HttpFetchProvider::followAndRead` (finding 340): resolving the redirect `Location` happens inside the try block that cancels the unfinished redirect body, so an unparseable `Location` such as `http://[` closes the response and still fails as `WEB_PROVIDER_ERROR`.

`packages/web/tool-web/src/fetch.ts:exceedsConversionDepth` (finding 338): a trailing slash closes an element only for void elements, for `svg`/`math` and elements inside them, and never for the HTML tags that break out of foreign content (`div`, `p`, `span` and the rest of the parsing standard's list), because the HTML parser opens those and leaves them open; `<div/>` repeated past the ceiling now trips the guard.

`packages/web/tool-web/src/fetch.ts:stylesheetHiddenSelectors` (finding 339): the visibility filter reads `<style>` rules once per conversion, bounded to 20 style elements, 20,000 characters each and 200 selectors, and treats a rule with `display:none` or `visibility:hidden|collapse` and a simple class, id or tag selector as hiding matching elements. Combinators, attribute selectors, media queries and external stylesheets are not evaluated, so the filter stays best-effort and is documented as such. `packages/web/tool-web/src/fetch.ts:hidingSelectors` scans the braces once with a stack, so a long brace-free run costs linear time (the earlier regex `/([^{}@]+){([^{}]*)}/gu` backtracked quadratically, about 400 ms for one 20,000-character run). Every block inside an at-rule (`@media`, `@supports`, `@font-face`) and every block nested inside a rule is skipped, because a conditional `display:none` does not hide the element unconditionally.

`packages/web/web/src/types.ts:WebFetchResult` (finding 343): `url` is now always the URL the request named. `finalUrl` is the URL after allowed redirects, and `statusCode` is the HTTP status; both are `null` when the provider cannot observe them. The earlier shape made `url` the final URL and let a provider fill an unobserved status with 200, which the DeepSeek Fetch adapter did. The HTTP provider reports both fields; the DeepSeek Fetch adapter reports neither.

`packages/web/tool-web/src/fetch.ts:computeFetchOutput` (finding 343): the header names `finalUrl` when it is reported and the requested URL otherwise. The parenthetical names what is missing: `HTTP <n>` when both values are known, `HTTP status not reported by the fetch service` or `final URL not reported by the fetch service` for a single gap, and `HTTP status and final URL not reported by the fetch service` when both are missing. The model-facing text is the only place a status gap appears in words, so it must not read as a 200.

`packages/web/tool-web/src/fetch.ts:fetchMetaFromResult` (finding 343): replayed meta written before this change has no `finalUrl` key. That key meant the URL was the final URL, so an absent `finalUrl` reads as `url`. An absent `statusCode` reads as `null`. Records written by the DeepSeek Fetch adapter before this change carry a fabricated `statusCode: 200` that cannot be told apart from a real 200, and they keep that value on replay.

`packages/web/tool-web/src/fetch.ts:applyWebFetchTool` (finding 343): the output schema declares `finalUrl` and `statusCode` as `oneOf` a value or `null`, required, so the explicit unknown survives output validation and is not dropped to an absent key.

`packages/client/ui-tool/src/client/tool/models/web-card-model.ts:webCardModel` (finding 343): mirrors `fetchMetaFromResult` for client replay. It links the final URL when one is reported and sets `finalUrlUnreported` only when `finalUrl` is `null`, so a legacy record with no `finalUrl` key shows no gap.

`packages/web/web-deepseek-api/src/fetch.ts:DeepSeekFetchApiProvider::fetch` (finding 343): the Fetch API response carries the page content only. The adapter returns the requested URL, `finalUrl: null` and `statusCode: null`. Its class doc no longer says the page was retrieved with HTTP 200.

`packages/web/web-fetch-http/src/provider.ts:HttpFetchProvider::fetch` (finding 343): the HTTP provider returns the requested URL as `url` and the post-redirect URL as `finalUrl`, which it observes, so it sets both.

`packages/experimental/deepseek-chat-import/src/conversation.ts` (finding 343, decision): an imported transcript records a successful open of a URL but not its status or redirect target. The import now writes `statusCode: null` and `finalUrl: null` rather than inferring 200, so the card reports both as not reported. The DeepSeek import README documents the earlier inference, which is no longer made.

`packages/web/tool-web/src/fetch.ts:fetchMetaFromValue` (finding 343, decision): `presentFetchResult` builds the card from `finalUrl ?? url`, and its `finalUrlUnreported` flag is set when `finalUrl` is `null`. The card is the only surface that renders an unobserved final URL as a gap; the header text and the card agree because both read the same two fields.

`packages/web/web/src/index.ts:readBoundedJson`: the entry no longer re-exports the safety helpers. Sibling provider packages (`web-deepseek-api`, `web-search-deepseek`, `web-search-exa`, `web-search-perplexity`) import them from the `@deepseek-ai/dsh-web/safety` subpath, which the package manifest exposes at `lib/types/safety.js`. This keeps the entry to the Loader four and the Service and error classes.

`packages/web/web/src/index.ts:redactEndpoint`: same as `readBoundedJson`; reached through `@deepseek-ai/dsh-web/safety`.
