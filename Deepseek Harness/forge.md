# forge code notes

`packages/experimental/forge/src/types.ts:ForgeReviewWrite`: the `headSha` contract said providers refuse a write with `stale` once the head is another commit, which read as a guarantee that no write lands after a push. The host calls the provider makes are a head read followed by a separate mutation, and GitHub offers no head precondition on those mutations, so a push between the read and the mutation can receive the write (issues.md finding 385). The contract now says the provider checks the head before writing and that a push after the check can still receive the write; `stale` means the head moved before the check. The same narrowing applies to `ForgeViewedRequest` through `setViewed` in `packages/experimental/forge/src/types.ts:ForgeProvider::setViewed`. Callers keep their own reconciliation: after any write the registry polls a watched change request, so the next status shows the head the write landed on. Merge and branch update are not in this entry: GitHub's merge and update-branch endpoints take an expected head, so their check is atomic on the host.

`packages/experimental/forge/README.md:ForgeProvider::setViewed`: the README sentence on `setViewed` and `writeReview` carries the same narrowed contract as the types file. No revert-proof test: the change is documentation only.
