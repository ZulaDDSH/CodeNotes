# product-analytics code notes

## packages/client/product-analytics/src/index.ts:ProductAnalytics::report

Findings 375-377 and 379 (Host intake part). Finding 375 was first rejected as a documented limit; the owner overturned that, and the control is the Desktop General settings row described in the `ProductAnalytics.Config` entry below. Finding 376: the identity lookup is bounded by `settleWithin` with `IDENTITY_DEADLINE_MILLIS` (5 seconds, matching the environment query default); on expiry the event is emitted without `device_id` and `user_id`, the same omission used for a rejected lookup, and the late result is discarded. Finding 376: `ProductAnalytics::trackIdentity` counts provider calls until each one settles rather than until the deadline, so `MAX_IDENTITY_LOOKUPS` (64) bounds stalled provider calls over time; at the cap no provider call is made and the event is emitted without identity fields. Finding 376: at most `MAX_PENDING_REPORTS` (256) reports may await identity or environment at once; a report beyond the cap is dropped without retaining its payload and without a drop counter, so the pending reports are bounded by the cap rather than by the event rate. Finding 377: `policyGeneration` advances on every `loader/volatile-update` observed while collection is disabled, so a report admitted before a disable is discarded at submission even when the policy was re-enabled during its wait; this relies on Loader emitting that event after each volatile update, as the existing policy watchers already do. Finding 379: string attribute values longer than `MAX_STRING_ATTRIBUTE_BYTES` (256 UTF-8 bytes) are replaced with the fixed marker `[oversized]` before emission, so the original contents are never queued; the replacement is not counted or logged. Finding 379 remainder: an encoded-byte budget for the OTel queue is not implemented here; it is deferred as described under `ProductTelemetry::emit`.

## packages/client/product-analytics/src/index.ts:settleWithin

Finding 376. The helper resolves with `undefined` at the deadline and clears its timer on either outcome, so a completed lookup does not leave a timer behind. It does not cancel the underlying work; the lookup's own settlement is tracked by `ProductAnalytics::trackIdentity`.

## packages/client/product-analytics/src/index.ts:ProductAnalytics::trackIdentity

Finding 376. The outstanding count increments only after the provider call returns, so a synchronous throw from `getDeviceIdentity` leaves the count unchanged and falls through to the existing report-level failure log. The count decrements when the lookup settles, whether it fulfils or rejects, so a stalled provider holds at most `MAX_IDENTITY_LOOKUPS` slots.

## packages/host/product-telemetry-otel/src/index.ts:ProductTelemetry::emit

Finding 379, deferred. The exporter bounds queued records by count (`maxQueueSize`) through the OTel SDK, and no encoded-byte budget is enforced here. A single record is bounded by the client sanitizer and the Host attribute cap, not by a queue byte budget. Adding a byte budget needs a queue-admission design (which records to drop, and whether to count them) that is not decided in this pass; this is recorded as NEEDS NOMAD.

## packages/client/product-analytics/src/index.ts:ProductAnalytics.Config

Finding 375. `enabled` now defaults to false and the Desktop composition row in `packages/bundle/web-app/cordis.patch.yml` ships `enabled: false`, so collection is opt-in: nothing is inspected, queried or emitted until the user turns the General settings row on. Existing profiles never held a saved value (there was no control), so they move to off as well; a user who wants collection turns it on once. The field stays volatile, so the row's write applies live through the existing `loader/volatile-update` path, `watchPolicy` reaches the renderer sender, and the Host re-checks the policy at intake and after the environment and identity lookups, which discards an event admitted just before the user turned the row off (`policyGeneration`). The row's write persists through the Settings service into the active profile patch, which sits above the shipped bundle patch, so the choice survives restarts. Events already handed to the OTel exporter before the switch are not recalled: the exporter finishes delivering what it has queued, as the package README states, and the row's description says so. The Settings form stays hidden (`configure({ auto: false })`) because the row is the control. Ordinary Web does not mount the service, so `configForms.whileServed` never registers the row there.
