# ui-provider-quota code notes

## packages/client/ui-provider-quota/src/client/usage-prompt.ts:localUsagePromptStore

`packages/client/ui-provider-quota/src/client/usage-prompt.ts:localUsagePromptStore`: Finding 175 (getter) and 199 (methods). The default storage argument evaluated `typeof localStorage` at call time and threw when the getter is blocked; it now uses `browserStorage()` from `@deepseek-ai/dsh-client-store`. The store's `getItem`/`setItem`/`removeItem` calls were unguarded, so a quota or policy error rejected controller construction, dismissal, and a provider switch after the remote setting had already changed. Every storage call is now wrapped: a read failure reads as no saved value, a write or remove failure is ignored, and the in-memory prompt state keeps working for the page.

## packages/client/ui-provider-quota/src/client/controller.ts:ProviderQuotaController (findings 295 client, 296)

- `packages/client/ui-provider-quota/src/client/controller.ts:ProviderQuotaController.refresh` - `refresh()` started a second load while an earlier one was still running, and neither the provider-list response nor the final results were tied to the request that asked for them, so an older response finishing last replaced a newer list or newer quota results with its older snapshot. Every `load()` and `refresh()` now takes a new `generation`, `loadProviders` and `fetchConfigured` capture it and publish nothing when it is no longer current, and `refreshValues` captures the current generation without advancing it so a values refresh can be superseded by a later reload but never supersedes a list load in progress. A superseded call still resolves, it just does not publish. Previous work is not cancelled (the Remote API has no cancel), only discarded.
- `packages/client/ui-provider-quota/src/client/controller.ts:ProviderQuotaController.fetchConfigured` - the aggregate waited on every provider call, so one call that never settled kept the whole view loading and withheld finished providers. Each per-provider call now races a client deadline (`fetchTimeoutMs`, default 45000 ms, above the Host's 30 s whole-read deadline so the Host's own failure message normally wins); a call that misses it counts as that provider's failed read (`configured: true, ok: false`, error `Quota request timed out`) and the others publish normally. The abandoned call keeps running and its late answer is ignored.

## packages/client/ui-provider-quota/src/client/controller.ts:ProviderQuotaController (finding 402)

- `packages/client/ui-provider-quota/src/client/controller.ts:ProviderQuotaController::switchBilling` - The popover's switch to API credits passes no reset, so the saved switch carried no `resetAt` and `usagePrompt` never offered the switch-back. A switch to API credits now saves `resetAt` as the reset of the window it answers when the caller supplies one, and otherwise a day after the switch (`OPEN_WINDOW_HOLD_MS`), the same fallback the composer prompt uses. Decision: manual popover switches get a switch-back offer; the offer comes one day after the switch rather than at a subscription window's reset because the popover does not choose a window. Persisted shape: `dsh.provider-quota.switched` now always holds a numeric `resetAt` for a switch written after this change; values stored before it are read unchanged and are not migrated. Upgrade path: take the most-constrained window's reset in the popover if the one-day offer proves too late.

## packages/client/ui-provider-quota/src/client/usage-prompt.ts:usagePrompt (finding 401)

- `packages/client/ui-provider-quota/src/client/usage-prompt.ts:isDismissed` - A dismissal matched any entry with the same provider prefix, so "Not now" on one window hid every other window of that provider, including a newly reported hard limit, until the dismissed window's expiry. Matching is now scoped to the provider and window (`limit|provider|window`, or `hard|provider|window`) and to the entry's expiry, so other windows of the same provider prompt normally. The test that asserted the broader suppression was rewritten to assert window scope.
- `packages/client/ui-provider-quota/src/client/usage-prompt.ts:limitKey` - A hard limit now uses the `hard|` prefix instead of `limit|`, so declining a near-limit warning does not hide a later hard limit on the same window. Decision: escalation from near-limit to hard-limit reappears; the reverse (a hard limit that clears to near-limit after a hard dismissal) also reappears, since it is a different prompt. Persisted shape: `dsh.provider-quota.dismissed` entries for hard limits written after this change start with `hard|`; entries written before keep their `limit|` form and suppress only the near-limit prompt for that window until their stored reset.
- `packages/client/ui-provider-quota/src/client/usage-prompt.ts:withDismissed` - A new dismissal replaces any remembered key for the same provider, window and severity, whatever its reset, so a window's dismissals do not accumulate across resets. Reset-time changes: a dismissal holds until the reset recorded when it was dismissed; a provider that moves the reset later re-prompts at that recorded instant. This is an accepted limit, not a suppression that follows the moved reset.
- `packages/client/ui-provider-quota/README.md` - Documents the window scope and the hard-limit exception for "Not now".

## packages/client/ui-provider-quota/src/client/usage-prompt.ts:withDismissed

A `back|<provider>|<resetAt>` entry is dismissed after its reset instant by construction (the offer only shows once `now >= resetAt`), so the generic `reset >= now` expiry dropped it on the next unrelated dismissal and the switch-back prompt returned. Back entries are exempt from that expiry and kept for `BACK_DISMISSAL_HOLD_MS` (30 days) past their reset instant, then forgotten so the list stays bounded.

### `packages/client/ui-provider-quota/src/client/ProviderQuotaAction.tsx:WINDOWS`

the popover draws only the window ids listed here, in this order, so a new `QuotaWindowId` must be added here and to the `window.<id>` and `span.<id>` strings in `locales.ts:zh` and `locales.ts:en`. `daily` reads "Today" and sits after `5h`.

### `packages/client/ui-provider-quota/src/client/usage-prompt.ts:WINDOW_HOURS`

the table is typed `Record<QuotaWindowId, number>` and its keys are also the list of windows `usagePrompt` scans, so `daily` is 24 hours. Its only use there is ranking: when several windows are near their limit the longest is shown first, so a near-limit `daily` window yields to a weekly or monthly one. A provider without a billing switch (Freebuff) gets the plain near-limit or hard-limit text and "pick another model", not an offer to switch to API credits.
