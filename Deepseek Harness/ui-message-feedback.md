# ui-message-feedback code notes

`packages/client/ui-message-feedback/src/client/MessageFeedbackActions.tsx:FeedbackRatingButtons`: clicking a recorded rating used to retract it immediately, and withdrawal is itself an export trigger (a `feedback/message-delete` event authorizes the telemetry backend to release the conversation prefix), so a user removing a rating could send the transcript without being told. The click now opens a confirmation (`withdraw.title`, `withdraw.body`, `withdraw.cancel`, `withdraw.confirm`) that states the release, and only the confirm button calls `retract`; cancelling or closing leaves the rating and sends nothing. The copy names the live sharing policy read through `sessionFeedback.sharing` (see `docs/code-notes/command-feedback.md`) and falls back to the generic conditional copy when the read fails or has not settled. Covered by `packages/client/ui-message-feedback/tests/message-feedback-actions.client.spec.tsx`.

`packages/client/ui-message-feedback/src/client/FeedbackDialog.tsx:FeedbackDialog`: the only disclosure in the dialog was the textarea placeholder, which disappears once text is typed. `dialog.disclosure` is now a persistent note under the category chips naming the scope (the conversation so far), the destination (the configured feedback collector) and the condition (session telemetry enabled), and that withdrawing a rating also exports.

`packages/client/ui-message-feedback/src/client/dialog.ts:FeedbackDialogController`: the dialog now carries `localOnly` in its draft state, shown as a checkbox ("Keep on this device only"), and passes it with every submission: a message target sends it on `messageFeedback.put` and a Session target on `sessionFeedback.record`. The draft starts unchecked because the default behaviour of ratings is unchanged; the choice is per submission and is discarded with the draft. The controller also reads `sessionFeedback.sharing` on every open and exposes it as `FeedbackDialogState.sharing` (`null` until settled or when the read fails), so `dialog.disclosure` can name the live policy and destination: `disabled` or `none` says nothing leaves the device, `feedback-only` and `full` name the collector origin, and `null` keeps the generic conditional copy. Checking the box swaps the disclosure for the local-only statement. Covered by `packages/client/ui-message-feedback/tests/dialog.client.spec.ts` and `packages/client/ui-message-feedback/tests/feedback-dialog.client.spec.tsx`.

`packages/client/ui-message-feedback/src/client/MessageFeedbackActions.tsx:FeedbackRatingButtons`: the withdrawal confirmation has a "Withdraw without sending the conversation" checkbox; confirming passes `localOnly` to `retract`, which sends it on `messageFeedback.delete`. The confirmation reads the live sharing policy from the same dialog state so the body names the real destination. Covered by `packages/client/ui-message-feedback/tests/message-feedback-actions.client.spec.tsx`.

## Passive views revalidate on focus and when a control returns; idle views are evicted (findings 417 and 418)

- `packages/client/ui-message-feedback/src/client/controller.ts:MessageFeedbackController::subscribe` marks a ready view stale when its last subscriber leaves, and a later subscriber triggers `resync` for it. This covers the navigation case in 417: the cached surface is re-read when a row mounts again, instead of serving the rating another client changed while this one was elsewhere.
- `packages/client/ui-message-feedback/src/client/controller.ts:MessageFeedbackController::ensure` returns the cached view only when it is ready and not stale. A stale view that nothing watches (for example a dialog submission made without a mounted row) re-reads through `refresh` before the mutation's compare-and-set runs.
- `packages/client/ui-message-feedback/src/client/controller.ts:MessageFeedbackController::evict` drops a view to `cold` only when no control watches it. `packages/client/ui-message-feedback/src/client/index.ts` calls it for every unwatched surface on `connection/reset`, which bounds the reconnect burst in 418 to the Sessions currently on screen.
- `packages/client/ui-message-feedback/src/client/index.ts:apply` resyncs watched ready views on window `focus`. The handler listens to `focus` only, not `visibilitychange`, so one tab switch produces one read per watched Session. Focus is the boundary for another client's change to a passive view in 417; it is not a push channel, so a change made in a window that never receives focus is seen at the next focus, mount, or mutation.
- Decision: no new Remote or event is added. The `message-feedback` service has no change feed, and adding one would change the Remote contract, which is out of scope here. Revalidation uses the existing list read.
- Residual for 418: surface objects (the controller and dialog state) are still kept for every visited Session until the plugin unloads. Disposing one is not safe while the dialog can open without a mounted subscriber (`feedbackUi.openSession`), so only the loaded feedback items are released. The loaded items of idle Sessions are kept until the next reconnect or unload, so memory is bounded by visited Sessions' feedback, not by a fixed cap.
- The reconnect path no longer re-reads Sessions with no watcher, which removes the growing per-reconnect list burst. Cold list reads still read the Session log on the Host when a row is hovered after eviction.
- Covered by `packages/client/ui-message-feedback/tests/controller.client.spec.ts` (stale revalidation on re-subscribe; evict keeps a watched view and drops an idle one) and `packages/client/ui-message-feedback/tests/browser-plugin.client.spec.tsx` (reconnect resyncs only watched Sessions and evicts idle ones; focus resyncs only watched ready Sessions).
