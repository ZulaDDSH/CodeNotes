# session-title code notes

`packages/session/session-title/src/index.ts:collectSessionTitleMessages`: finding 325 remaining part. The service used to materialize the joined, normalized text of every eligible human message through the revision before the provider could decide anything, so the scan and string work grew with the whole history. When a provider declares `messageBudgetBytes`, the scan walks backward from the revision watermark, materializes text only for messages it keeps, stops keeping once the next message would exceed the budget, and always keeps the newest eligible message so a provider still receives an attempt (an oversized newest message then fails with the executor's normal `maxInputBytes` error). Older eligible messages are counted, not read: `omitted` uses a cheap visible-character test per text block, so a message made only of control or escape characters can be counted here while `normalizeSessionTitle` would drop it. The count is sent to the provider as `SessionTitleProviderRequest.omittedMessages` so the provider can say that context was omitted. The snapshot event array is still copied once per log change and the backward walk still touches each older event's type once, so the remaining linear part is a pointer walk; incremental retention of eligible messages in the projection would remove it and is not built.

`packages/session/session-title/src/index.ts:SessionTitleProvider`: the optional `messageBudgetBytes` field declares the per-generation byte budget of collected message text; the service rejects a non-positive or non-integer value at registration.

`packages/experimental/session-title-all-prompts-llm/src/index.ts:frameWithinBudget`: now receives the service's omitted count and adds it to the count it trims itself, so `omittedEarlierMessages` covers both kinds of omission.
