# working-directory code notes

`packages/session/working-directory/src/index.ts:WorkingDirectoryService::set`: the `working-directory/access` event carried the requested path as typed, so a listener that resolved directories (the worktree removal gate) compared a relative path such as `../checkout` against an absolute checkout root and let it through while removal was registered (issues.md finding 387). `set` now resolves the requested path against the Session's committed directory inside the serialized operation, before the waterfall, and passes that canonical absolute path (`fs.resolve` then `fs.processPath`, the same resolution the body already used) as the event path. The body commits the canonical path. An empty path is passed through unchanged so the `cd must not be empty` rejection still comes from the waterfall body. Consequence: a missing directory's error text now shows the canonical path rather than the path as typed. Covered by `packages/experimental/worktree/tests/archive.spec.ts` (relative entry into a checkout being removed) and `packages/session/working-directory/tests/working-directory.spec.ts`.
