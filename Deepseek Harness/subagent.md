# subagent code notes

## packages/subagent/subagent/src/manager.ts:SubagentManager::deliverToMember (issue 33)

Inbox admission is synchronous and in memory; the JSONL backend batches the resulting `inbox` event, so `send_message` and host prompts used to return a message id before the insertion was on disk. A crash in that window lost an accepted instruction with no replay.

Fix: after the per-child lock is released, the accepted target's Session is flushed (`ctx.sessions.flush`) before the id is returned. The flush runs outside the lock so other deliveries are not serialized behind storage latency, and it never un-accepts: the message is already in the live inbox and will run. A flush failure is logged and the id is still returned, because retrying would duplicate a message that is already queued; the id is the stable identity of the accepted message. Memory-only sessions flush as a no-op.

## packages/subagent/subagent/src/manager.ts:SubagentManager::interrupt (issue 60)

The README's "wake gap during cancellation convergence" limitation was stale: `interrupt` cancels with `keepInbox`, delivery uses the waking `steer`/`followup`, and `Agent.send` classifies a waking send after abort as next-turn input, latches the wake and replays it when the aborted driver converges. The regression `runs a send_message accepted between interrupt and idle once the child converges` in `tests/continuation.spec.ts` passes on unmodified code, confirming the finding. The distinct driver-retirement race (input landing after the final inbox check) is closed in `packages/core/agent-loop/src/agent.ts:Agent::kick` (issue 24), so no limitation remains.

`packages/subagent/subagent/src/out-of-process.ts:assertExternalCwdWithinParentWorkspace` (finding 178): an external child (Codex, Claude Code, ACP) receives its own native workspace from the cwd the provider is started in, but the sandbox clamp passes only the parent's mode, so a `workspace-write` parent could name any enterable directory and make it the child's writable root. `SubagentManager.startExternalNamed` now checks the resolved cwd after `resolveDirectory` and before the provider starts. Under any parent mode other than `danger-full-access` (or `read-only`/`workspace-write` resolved by `ctx.sandboxPolicy`), the physical (realpath) cwd must be inside the physical parent workspace root or one of its `additionalWritableRoots`; relative `..` traversal is caught because the path is resolved first and symlinks because both sides are realpathed. Without a composed `sandboxPolicy` the check is skipped, as for the Codex clamp. A cwd that does not yet exist is compared lexically and left to `assertUsableCwd`. In-process children are not affected: their Session keeps the parent's immutable header cwd as the workspace root. Limit: the check is one-time at start; a child that is a native agent can still choose its own paths inside the granted root.

`packages/subagent/subagent-acp/src/index.ts:AcpProvider.start` (finding 177): the ACP child is an ordinary host-account process; `permission: reject` only answers prompts the child chooses to send, and a working directory is not a filesystem boundary. The provider cannot attest or enforce the parent's sandbox, so start now refuses with `PARENT_SANDBOX_MISMATCH` unless the parent session resolves to `danger-full-access` or no `sandboxPolicy` is composed. The `allowRestrictedParent` config flag is an explicit operator attestation that the command is contained externally (container, OS sandbox); it defaults to false.

`packages/subagent/subagent/src/manager.ts:SubagentManager::materializeTracked` (finding 179): an external child that stays alive but never answers its initialize or session-creation request kept the reserved tree slot and the waiting tool call until the caller cancelled. The external branch now races the provider start against a startup deadline (`EXTERNAL_STARTUP_TIMEOUT_MS`, five minutes, module private). On expiry the startup signal is aborted with a `STARTUP_TIMEOUT` `SubagentError`, which the provider's own cancellation path uses to kill and reap the child, the failure message names the stage that was pending (`provider start: initialize and session creation`), and the existing catch in `materialize` releases the slot. A provider that ignores the signal cannot hold the slot either: the race rejects at the deadline and a run that resolves later is disposed instead of leaking. The manager cannot tell initialize from session creation, so the stage is the provider handshake as a whole; a provider's own error text may be finer. The deadline is not configurable because a new config field would need the generated catalog; Codex's optional run timeout still starts only after the handshake.

packages/subagent/subagent/src/catalog.ts:subagentCatalogProjectionDefinition (finding 346): the catalog state is a `ChunkedList` whose checkpoint shape changed from a linked chain of 64-fact nodes to bounded-height blocks (see `docs/code-notes/chunked-list.md`, `packages/util/chunked-list/src/index.ts:appendChunkedList`), so `stateVersion` moved from 6 to 7. A cached version-6 row is no longer read; the projection cache treats a version mismatch as absent and the catalog is folded again from the parent's `subagent/catalog` events, which are unchanged and remain the only source of truth, so no child record is lost and a session's first load after the upgrade pays one replay.

packages/subagent/subagent/src/manager.ts:SubagentManager::reserveName (finding 345, name reservation only): every named or unnamed child creation materialized the parent's whole catalog view and built a set of every earlier name, so a long-lived parent creating N children did quadratic total work. The manager now keeps one committed-name set per live parent `Session` (`committedNames`, a `WeakMap`), seeds it from the catalog view on the first reservation for that Session object only (so a rehydrated or reloaded parent re-reads its durable catalog once), and adds each name right after `establishCatalogChild` or `establishExternalCatalogChild` succeeds; a failed append adds nothing. Those two calls are the only writers of the parent's catalog in this process, which is the invariant the set relies on. `SiblingNameReservations::reserve` also keeps a per-set ordinal hint for default `agent-N` names: committed names are append-only, so the probe resumes after the last committed ordinal it passed instead of restarting at 1, while a name held only by an in-flight reservation never advances the hint because its release makes it free again. Not changed: the projection's wire publication still materializes and validates the full catalog view on every catalog change (`packages/session/session-projection/src/index.ts`, the `wire.view` publish path), so connected-client traffic stays proportional to the number of children; delta or paged publication needs a wire-protocol change and is left as a decision. Superseded by the keyed catalog index entries at the end of this file (finding 345, strict O(path)).

`packages/subagent/subagent/src/catalog.ts:subagentCatalogProjectionDefinition` (finding 345, publication): the wire unit declares `appended`, so an event that only appends a catalog fact publishes `{ from, items }` for the new entry instead of the whole view. The view length before the change is the count of prior facts, which is the same as the entry count because every catalog event adds exactly one entry. The view and state shapes are unchanged, so `stateVersion` stays 7. The follow-open baseline still carries the full catalog once per open; paging that baseline is a separate decision. Superseded by the keyed catalog index entries at the end of this file (finding 345, strict O(path)).

`packages/subagent/subagent/src/manager.ts:SubagentManager::finishDisposal`: finding 281. The backend handle (`handle.dispose()` or `run.dispose()`) is now attempted up to `TEARDOWN_ATTEMPTS` times inside `finishDisposal`, through `SubagentManager::disposeHandle`. Only after the last attempt fails is the failure recorded, and `activation.handleUndisposed` is set so the remaining cleanup still runs once (resident removal, slot release, `subagent/end`, result settlement).

`packages/subagent/subagent/src/manager.ts:SubagentManager::dispose`: a `closing` memo that rejected before this change was returned forever, so a caller retrying a failed teardown never reached the backend again. When `handleUndisposed` is set, `dispose` re-drives only the backend disposal through `SubagentManager::redriveHandle`, which swaps in a new `closing` promise (`closing` stays defined, so it remains the admission-closed flag) and shares that promise with concurrent callers. The re-drive never repeats `subagent/end`, parent notification, or slot release.

The local handle is an agent-loop disposer that now resumes at the teardown step that failed (see agent-loop.md, finding 281), so a retried `handle.dispose()` can succeed after a transient failure and every attempt in `disposeHandle` is meaningful for both local and external handles.

`packages/subagent/subagent/src/manager.ts:SubagentManager::finishDisposal`: finding 281, stop path. The manager's own idle wait after `cancel` (`Agent.whenIdle`) was a single attempt, so one transient rejection skipped the final flush and result capture, recorded the failure and rejected the activation result even when the later handle disposal succeeded. The wait now runs through `SubagentManager::attempts`, the same bounded loop `disposeHandle` uses (`TEARDOWN_ATTEMPTS`, three tries, no timer: the workflow README documents the absent abandonment timer as deliberate). A recovered wait continues to the final flush and `captureLocalResult` and reports no failure. When every attempt rejects, the last error is recorded as `ACTIVATION_TEARDOWN_FAILED`, the result promise rejects with it, `subagent/end` fires once with `stopReason: error`, and a later `dispose()` returns the same memoized rejection without a second `subagent/end`. Only a failed handle disposal (`handleUndisposed`) is re-driven by a later `dispose()`: a failed idle wait does not mean a resource is still held, so it is reported, not retried indefinitely.

`packages/subagent/subagent/src/manager.ts:SubagentManager::resolveCreationAncestry` (finding 345, residual a): the creator walk used to call `observeContinuation` for every hop, and each hop folded the creator's whole projection set, including the full `subagentCatalog`, just to find one child id. A creator that is live in this process now answers from its committed catalog index (`SubagentManager::liveCreationParent`) and never observes its log. The walk still reads the creator's identity from `host.identityOf`, so the identity and seq checks are unchanged. A miss on the live index falls through to the observation path, which keeps the original `UNAUTHORIZED` result.

`packages/subagent/subagent/src/manager.ts:SubagentManager::committedCatalog` (finding 345, residual a): the per-Session committed index holds both the sibling-name set and a child-id to name map. Both are seeded from `host.catalogOf` once per Session, which is the only catalog read on the live path after the first creation. `SubagentManager::recordCommitted` adds each establishment to the index, at the same two sites that already added the name. The index is append-only, so it matches the catalog projection, which never removes an entry. Superseded by the keyed catalog index entries at the end of this file (finding 345, strict O(path)).

Limit: a dormant intermediate creator still goes through `observeSession`, which materializes every projection of that Session, so the walk stays O(catalog size) for dormant hops. A keyed read (`projectionMode` with a key list) in session-query would remove that cost. The residual is recorded as PARTIAL in the finding report.

`packages/subagent/subagent/tests/ancestry-index.spec.ts` (finding 345, residual a): cold delivery under a live root observes only the child's own log, and reads the root's catalog at most once, when the index is first seeded. Superseded by the keyed catalog index entries at the end of this file (finding 345, strict O(path)).

`packages/subagent/subagent/src/manager.ts:SubagentManager::liveCreationParent` (finding 345, residual a, trust rule): for a creator that is live in this process, the committed index is trusted over the creator's stored log evidence. A stored `subagentCatalog` row for a live creator is not consulted, so injected or corrupt stored evidence for a live branch no longer changes the answer. `packages/subagent/subagent/tests/sibling-messages.spec.ts` (the `missing` and `cyclic` creation-evidence cases) therefore interrupts and settles the branch first and asserts `ctx.agents.get(branchId)` is undefined before corrupting evidence, so the observation path is exercised.

packages/subagent/subagent/src/manager.ts:SubagentManager::resolveCreationAncestry (finding 345, dormant hop): a creator that is not live was read with `observeContinuation`, which materializes every registered projection of that creator and then `.find`s the child in the catalog view. The hop now reads the creator through `SessionQueryEngine::inspectSession` (projection-free live-or-prepared cut) and asks only for its `subagent` identity (`Host::identityOf`) and its child index (`SubagentManager::committedCatalog`, the child-to-name map). No other unit is computed and no event array is copied. The UNAUTHORIZED "absent from its creator catalog" check is kept: a missing child id still throws.

packages/subagent/subagent/src/manager.ts:SubagentManager::committedCatalog (finding 345, dormant hop): the child index is built from the catalog projection state (`Host::catalogChildrenOf`, a walk of the chunked list), not from `Host::catalogOf`, so building it never materializes the wire view of the catalog. The index is cached per Session object in a `WeakMap`, so it costs one O(catalog) walk per cut of a parent and O(1) per later hop on that cut. The first hop into a given dormant parent cut is therefore linear in that parent's catalog, not O(path); a strictly O(path) read needs an on-disk index and is a decision left open. A prepared cut is replaced when its revision changes, so a stale index is never reused across appends. Superseded by the keyed catalog index entries at the end of this file (finding 345, strict O(path)).

packages/subagent/subagent/src/index.ts:SubagentRuntime::init (finding 345, dormant hop): the `catalogChildrenOf` host member walks the catalog state head once and maps each child id to its name (`undefined` for versions without a name). It replaces the view-based `catalogOf` member as the source of the name index. Superseded by the keyed catalog index entries at the end of this file (finding 345, strict O(path)).

`packages/subagent/subagent/src/external-cwd.ts:assertExternalCwdWithinParentWorkspace`: moved out of `out-of-process.ts`. The subagent entry re-exports every value of `out-of-process.ts` through `export *`, which would make this function an entry export; keeping it in a separate module leaves the entry's surface unchanged. `manager.ts` and the spec import it from the new module.

### `packages/subagent/subagent/src/catalog.ts:SubagentCatalogState`

Finding 345, strict O(path). The state now carries two persistent keyed indexes beside the event list: `children` (child id to its name, `''` for an unnamed historical child) and `names` (name to the child id that holds it), plus `agentOrdinal`, the largest k for which `agent-1` through `agent-k` are all committed. They are maintained inside `apply`, so every consumer reads the state at the Session cursor instead of scanning the chunked list. The per-child entry is the parent pointer in the sense that a creator walk resolves a child id to its row in the creator's catalog by key. The event payload, the wire view and `appended` are unchanged; the chunked list stays the ordered source for the wire view.

The keyed reads are `catalogChild` (child id to `{ name }`, or undefined when absent, so the UNAUTHORIZED "absent from its creator catalog" check is unchanged) and `catalogHasName`; both serve the live and the dormant creation-ancestry hop and sibling-name reservation. None of them touch `head`; `catalog.spec.ts` replaces `head` with an object that throws on any access to prove it.

### `packages/subagent/subagent/src/catalog.ts:subagentCatalogProjectionDefinition`

Finding 345, strict O(path): `stateVersion` is 8. A version-7 checkpoint row has no index, and building one from its list would be the O(catalog) scan this change removes, so the registry's existing rule applies: a row whose `ver` differs is discarded and the key refolds from the full log once. Downgrade is the same in the other direction (an older reader discards a version-8 row). The view-compatibility test that reused a version-7 checkpoint now asserts the version-7 row is discarded and the version-8 row plus suffix replay equals a full replay. `apply` keeps the old failure rule: an invalid own fact throws and rejects restoration.

### `packages/subagent/subagent/src/keyed-trie.ts:insert`

Finding 345: a persistent string-keyed map whose nodes are plain JSON, because checkpoint rows must be plain JSON and `apply` must not mutate a previous state (`appended(prev, next)` and checkpoint seeding hold both). It is a 16-way hash trie over a 32-bit FNV-1a hash, eight nibble levels deep, so the checkpoint nests at most nine levels (finding 346 limits recursive depth). A set copies one node per level along the key's path and shares every other node, so an append costs O(depth * 16) independent of the catalog size. A slot holds either a one-entry leaf or a child node; a second key in a leaf's slot splits it one level down, and only after all eight nibbles are used does a leaf hold several keys (a full 32-bit collision), which then costs a scan of that bucket. Ceiling: names and ids are not attacker-chosen hash inputs in this host, so the bucket scan is accepted. `trieSchema` validates exact shape per level and, once at restore, that each entry sits on its hash path, so a corrupt row cannot hide a key from lookup.

### `packages/subagent/subagent/src/manager.ts:SubagentManager::reserveName`

Finding 345, strict O(path): reservation reads the parent's catalog state through `Host::catalogOf` and asks the `names` index and `agentOrdinal` directly. `committedNames`, `committedChildren`, `committedCatalog` and `recordCommitted` are gone: the projection already advances a Session's cell to its committed cursor on every `stateOf`, so an entry appended by `establishCatalogChild` is visible to the next reservation without a manager-side mirror, and the in-flight `SiblingNameReservations` set still covers names between reservation and commit. `SiblingNameReservations::reserve` takes `{ has, ordinal }` and starts the default `agent-N` probe at `ordinal + 1`, so a rehydrated parent no longer probes `agent-1` through `agent-N`.

### `packages/subagent/subagent/src/manager.ts:SubagentManager::resolveCreationAncestry`

Finding 345, strict O(path): both hops (`liveCreationParent` and `inspectCreationParent`) look the child up with `catalogChild` on the creator's catalog state. Remaining cost outside this change: a dormant creator is loaded by `SessionObservationReader::inspect` as a whole prepared Session (cold log read plus one fold of its events), because `inspectSession` has no keyed or checkpoint-only read. That cost belongs to the session-query cold-load path and applies to every projection, not to the catalog scan this finding named; with the index each fold step is O(1) per event instead of a second catalog walk.

### `packages/subagent/subagent/tests/ancestry-index.spec.ts`

Finding 345: the live and dormant ancestry tests replace `Host::catalogOf` with a view whose `head` throws on access. A path that falls back to scanning the list fails them. They replace the earlier assertion that the catalog was read at most once.

### `packages/subagent/subagent/src/manager.ts:SubagentManager::inspectCreationParent`

Finding 345, dormant hop. A creator that is not live is first resolved from its cached `subagentCatalog` and `subagent` checkpoint rows through `SessionQueryEngine::inspectCheckpoint`, with no persistence log read and no prepared Session. Only the keyed child index of the stored row is touched. A checkpoint is never authority: it may lag the log (the detach write is fire-and-forget, a crash can leave it behind), so it can prove that a child is present but never that one is absent. The fast path therefore answers only when the child is found in the row, and the row's own descriptor identity is usable. Every other case takes the previous full path, `SessionQueryEngine::inspectSession`, which loads and folds the creator's log: no cache service, no lifecycle-matching record, a row whose `ver` is not the unit's `stateVersion` (a version-7 catalog row), a malformed or mismatched row, a child absent from the row, or an identity the row cannot vouch for. The fallback is also what raises UNAUTHORIZED for a child that is truly absent from its creator's catalog.

### `packages/subagent/subagent/src/creation-checkpoint.ts:creationParentFromCheckpoint`

Finding 345, dormant hop. The catalog lookup walks only the raw hash path of the stored `children` trie (`trieGet` is total over unchecked input), so a hop costs the trie depth and not the catalog size; the full `stateSchema` parse is not run because it validates the whole chunked list and both tries on every hop. A malformed node reads as absent and therefore falls back. The row's `inheritedEventCount` must equal the cut recorded in the cache identity. The creator's identity is trusted only from the `subagent` row of the same record at the same watermark or later (the identity is last-wins, so an older watermark could be superseded) and only when it is the creator's own descriptor (`seq` at or after the inherited cut). A creator with no parent session needs no identity because the ancestry walk stops there. Residual: a row that is ahead of a crash-truncated log cannot be detected without reading the log; the cache's flush-before-put barrier in `SessionProjectionCache::write` is what rules it out.

### `packages/subagent/subagent/src/keyed-trie.ts:trieGet`

Finding 345: `trieGet` reads untrusted stored JSON on the dormant hop, so it checks the shape at every step (object slot, leaf array, string value) and returns undefined for anything else instead of throwing.
