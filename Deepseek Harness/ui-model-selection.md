# ui-model-selection code notes

`packages/client/ui-model-selection/src/client/directory.ts:ModelDirectory.select` (finding 220): the generation counter only suppressed the local settlement of an older response, while its `selectModel` request still reached the Host, so a delayed earlier choice could be applied after a later one and become the durable selection. Selections of one Session are now sent one at a time: a later choice waits for the in-flight request, and a choice that a newer one replaced before it was sent is dropped, its caller resolving as accepted because the newer choice supersedes it. With nothing in flight the request is sent synchronously. `resetConnected` and `dispose` abandon the wait so a request that never settles cannot block later choices. This orders only the choices of one browser client; two clients, or two tabs, selecting at the same time still reach the Host in network order, and the Host has no request sequence or revision to reject the older one. Decision for the lead: a Host-checked sequence would need a new field on `SessionSelectModelRequest` and a per-Session counter in `SessionCommandController::selectModel`, and is left undone.

`packages/client/ui-model-selection/src/client/directory.ts:ModelDirectory.select` (finding 222): a successful `selectModel` value carries `defaultSave`; `failed` sets `defaultNotSaved` on the shared store, which both the `/model` popup and the composer seat read, and the next selection or a connection reset clears it. `unavailable` (no configuration editor) and `pending` do not set it. `syncInputs` copies the flag through both of its `store.set` calls so a catalog or projection update cannot drop it. Both entries now show it with the `warning.defaultNotSaved` key, which is in all eight dictionaries and was appended to every non-zh/en list in `out-locales.json` by hand because no repo script generates that file.

`packages/client/ui-model-selection/src/client/index.ts:apply` (finding 222, popup entry): after a successful `/model` selection that left `defaultNotSaved` set, `onSelect` sends the `warning.defaultNotSaved` text to the session composer through `conversation.input.for(scope).notify('info', ...)`; the popup has already closed, so the composer notice is the only surface that can still be seen and it never blocks the next action.

`packages/client/ui-model-selection/src/client/ModelSelect.tsx:ModelSelect` (finding 222, seat entry): `submit` marks the selection as the seat's own through `ownSelection`, and once `pending` clears with `defaultNotSaved` set the existing composer Toast shows `warning.defaultNotSaved`; a flag raised by a `/model` selection does not toast here because that entry already notifies, which avoids a double notice. The seat menu closes on selection, so an in-menu strip would never be seen.

## packages/client/ui-model-selection/src/client/directory.ts:ModelDirectory::select

Finding 222. The Host reports `defaultSave: 'unavailable'` when the deployment has no configuration editor or no config entry, so the profile default was never written. The client previously set `defaultNotSaved` only for `'failed'`, so the no-editor case showed a successful switch with no notice. Both `'failed'` and `'unavailable'` now set `defaultNotSaved`. `'pending'` (the Host waited 3 seconds without an answer) is now followed through `session.defaultSaveOutcome`; see the finding 222 outcome endpoint entry on `ModelDirectory::select` below.

## packages/client/ui-model-selection/src/client/ModelSelect.tsx:ModelSelect

The default-not-saved toast carries a `warning.defaultRetry` action that clears the toast and resubmits the current selection. Re-selecting the same model re-runs the Host default save, so a retry either saves the default or shows the notice again. The toast holds for 30 seconds instead of the default hold so the action is reachable. The `/model` command notice in `index.ts` stays a plain info notice without an action (the command path has no action surface).

### `packages/client/ui-model-selection/src/client/directory.ts:ModelDirectory::select`

Finding 222 outcome endpoint. A `selectModel` value of `defaultSave: 'pending'` carries a `defaultSaveId`. The directory sets `defaultLate: 'saving'` and follows the save through `session.defaultSaveOutcome` in `ModelDirectory::followDefaultSave`, which repeats while the Host answers `pending` (the Host bounds each wait). A settled `saved` sets `defaultLate: 'saved'`; `failed` and `unavailable` set `defaultNotSaved`, and a rejected call (unknown id) is treated as not saved with the existing retry. The follow-up is dropped when the generation changes (a newer selection, `resetConnected`) or the directory is disposed, so an older save cannot overwrite a newer selection's state. `syncInputs` carries `defaultLate` through both `store.set` calls like `defaultNotSaved`. `DEFAULT_SAVE_FOLLOW_ROUNDS` (20) caps the follow; a save still pending after that many rounds is shown as not saved with the retry.

### `packages/client/ui-model-selection/src/client/ModelSelect.tsx:ModelSelect`

Finding 222. The own-selection flag now survives while `defaultLate === 'saving'`, so a late failure still raises the retry toast and a late success raises the `warning.defaultSaved` toast; the saving toast uses `warning.defaultSaving` without a retry action. `warning.defaultSaving` and `warning.defaultSaved` are in all eight dictionaries and were appended to `out-locales.json` by hand, like `warning.defaultNotSaved`.

### `packages/client/ui-model-selection/src/client/index.ts:apply`

Finding 222, popup entry. After `select` returns with `defaultLate === 'saving'` the popup has closed, so `onSelect` sends `warning.defaultSaving` to the composer and watches the directory store once; when `defaultLate` leaves `saving` it sends `warning.defaultSaved` (late success) or `warning.defaultNotSaved` (late failure), and sends nothing when a newer selection or a reset cleared it.
