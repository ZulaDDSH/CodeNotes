# ui-skill code notes

`packages/client/ui-skill/src/client/index.ts:fetchCatalog` (finding 411): a catalog result that reports `incomplete` is returned to the caller that asked for it but is not kept as the Session's settled catalog. The entry is removed silently, without a lexicon notification, so the next candidates read retries discovery. Notifying here would let an open menu refetch in a loop while a provider keeps failing.

`packages/client/ui-skill/src/client/index.ts:fetchCatalog` (finding 407): each entry records the Session's `workingDirectory` projection value at fetch time. `packages/client/ui-skill/src/client/index.ts:invalidateMovedDirectories` runs on every sessions list change and invalidates any entry whose recorded directory no longer matches the projection, which aborts an in-flight read and discards its result. The projection is the value the Host's catalog keys on, so the client invalidates exactly when the Host's answer can change for directory reasons.

`packages/client/ui-skill/src/client/index.ts:subscribeLexicon` (finding 408): when the last lexicon listener of a Session unsubscribes, the Session is marked released and a settled catalog is dropped at once. A fetch still in flight for a released Session is dropped when it settles, through `packages/client/ui-skill/src/client/index.ts:releaseUnobserved`. Input-trigger controllers subscribe for the life of a Session scope and unsubscribe on dispose, so that lifecycle is the eviction boundary. Sessions no controller ever observed, such as one read only by a reference preview, stay cached until an invalidation. The warm prewarm depends on that retention, since its settlement happens before a menu opens, so this limit is kept on purpose.
