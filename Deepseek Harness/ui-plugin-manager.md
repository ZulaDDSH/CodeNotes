# ui-plugin-manager code notes

## packages/client/ui-plugin-manager/src/client/manager-store.ts:settled

Findings 261, 262, 263, 264. The Gateway client throws before its carrier-error handling when no Connection service exists at dispatch, so the install start (`startInstall`), recovery (`reconcileInstall`), cancellation (`sendCancellation`), version lookup (`checkVersions`) and update (`runUpdate`) calls could reject instead of returning an error result. Each only handled the returned-error branch, so a rejection left `replyLost` false (recovery refused to run), `recovering` true (every later check returned early), the version check `checking`, the dialog `cancelling` and the update `running`. `settled` turns a rejection into a returned failure carrying its message, so each thrown call joins the existing uncertain-outcome branch: the install is marked reply-lost and reconciled by its original request id, a failed recovery clears `recovering` and stays retryable, a failed lookup settles as a retryable refusal, a failed cancellation is retryable, and a failed update shows the lost-result message. No duplicate installation starts because the original request identity is kept. Results are not tagged with a package/version generation beyond `dropStaleVersions` (limit).

## packages/client/ui-plugin-manager/src/client/sanitize-install-input.ts:sanitizeInstallInput

Findings 378 and 379 (client part). Registry-shaped input is returned unchanged only when it is at most `MAX_IDENTIFIER_LENGTH` (256 characters, above the 214-character npm name limit plus a version) and no `@`-separated segment looks like a credential; otherwise a credential-shaped identifier becomes `[credential-like]`, and an over-long registry-shaped string falls through to `[path-or-other]`. `isCredentialShaped` checks each `@`-separated segment against known token prefixes (`sk-`, `pk-`, `rk-`, `ghp_` and related GitHub forms, `github_pat_`, `xox*-`, `AKIA` followed by at least 8 uppercase letters or digits, `npm_`, `pypi-`, `glpat-`, `hf_`, and JWT `eyJ`) and treats a 32-plus-character alphanumeric segment containing both a letter and a digit as credential-shaped. Still passing: unprefixed tokens shorter than 32 characters, and keys that contain `-` or `.` without a known prefix, such as UUID-style keys; these are not treated as credentials. The detector can label a real package whose name starts with `sk-` as `[credential-like]`; that changes only the analytics value, never installation. Inputs that fail the registry grammar keep the `[git]`, `[url]`, or `[path-or-other]` buckets, so a credential that is not package-shaped is never echoed.

## packages/client/ui-plugin-manager/src/client/sanitize-install-input.ts:isCredentialShaped

The `sk`/`pk`/`rk` prefix is credential-shaped only when the remainder is at least 16 characters of `[a-z0-9_-]` and contains a digit, so package names such as `@sk-team/pkg`, `sk-utils` and `pk_helper` are kept while keys such as `sk-proj-abc123DEF456` are still redacted. The AWS access key id pattern (`AWS_ACCESS_KEY_ID`) is case-sensitive: real ids are upper case, and the case-insensitive form flagged `akiamusicplayer1`. Heuristic limit: a registry package named like `sk-long-name-with-a-digit-1` is still redacted.
