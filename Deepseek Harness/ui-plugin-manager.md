# ui-plugin-manager code notes

## packages/client/ui-plugin-manager/src/client/manager-store.ts:settled

Findings 261, 262, 263, 264. The Gateway client throws before its carrier-error handling when no Connection service exists at dispatch, so the install start (`startInstall`), recovery (`reconcileInstall`), cancellation (`sendCancellation`), version lookup (`checkVersions`) and update (`runUpdate`) calls could reject instead of returning an error result. Each only handled the returned-error branch, so a rejection left `replyLost` false (recovery refused to run), `recovering` true (every later check returned early), the version check `checking`, the dialog `cancelling` and the update `running`. `settled` turns a rejection into a returned failure carrying its message, so each thrown call joins the existing uncertain-outcome branch: the install is marked reply-lost and reconciled by its original request id, a failed recovery clears `recovering` and stays retryable, a failed lookup settles as a retryable refusal, a failed cancellation is retryable, and a failed update shows the lost-result message. No duplicate installation starts because the original request identity is kept. Results are not tagged with a package/version generation beyond `dropStaleVersions` (limit).

### `packages/client/ui-plugin-manager/src/client/sanitize-install-input.ts:sanitizeInstallInput`

Replaces the credential heuristics (the token-prefix list, the AWS key id pattern and the 32-character opaque-token rule of findings 378 and 379, listed as a heuristic limit) with an allowlist. A credential-shaped string and a real package name are the same grammar, so no pattern can separate them exactly; the exact rule is to report a registry name only when the caller says it is an official catalog entry (`officialNames`, built from the store's `PackageView.official` rows: shipped, optional and on-demand official bundles, never the profile's third-party or private packages). Any other registry-shaped input becomes `[package]`, so nothing a person typed is echoed unless it is an exact member of that set. A version after `@` is reported only when it matches the closed grammar `PLAIN_VERSION` (exact `x.y.z` with an optional `^` or `~`, an `alpha|beta|rc|next|canary` prerelease with an optional counter, or one of those names as a dist-tag); every other version becomes `@[version]`, so a pasted token after an official name is not echoed either. The output is bounded by the allowlist and the fixed labels, so the old 256-character cap is gone. The `[git]`, `[url]` and `[path-or-other]` labels classify by prefix and never echo the input. Behaviour change: third-party registry names that were reported before (`dsh-new`) are now `[package]`.

### `packages/client/ui-plugin-manager/src/client/manager-store.ts:runInstall`

Both analytics sites (`runInstall` and `approveBuildsAndRetry`) build the allowlist with `officialPackageNames` from the current snapshot and pass it to `sanitizeInstallInput`.
