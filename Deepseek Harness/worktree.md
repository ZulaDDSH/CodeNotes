# worktree code notes

`packages/experimental/worktree/src/removal.ts:inspectRemoval`: eligibility used `git status`, which reports neither ignored files nor edits to files marked skip-worktree or assume-unchanged, and `git worktree remove` without force deletes all three, so archiving a Session could destroy local configuration, generated data or hidden edits that its branch does not hold. Inspection now also retains a checkout that lists any ignored file (`git ls-files --others --ignored --exclude-standard`) or any tracked file whose `git ls-files -v` tag is not `H` (skip-worktree is `S`, assume-unchanged is lowercase). This is deliberately conservative: a checkout with only regenerable ignored output such as `node_modules` is also retained, and `retainOnArchive` plus manual removal remain the way to clean those. Covered by `packages/experimental/worktree/tests/removal.spec.ts` and `tests/archive.spec.ts`.

`packages/experimental/worktree/src/archive.ts:WorktreeReclamation::remove`: a directory access that the `working-directory/access` gate admitted before the removal registered its checkout was not waited for, so the removal's locked recheck could find the session still outside the checkout and remove it while the access then committed a working directory inside it (issues.md finding 387). The listener now records each admitted access (`WorktreeReclamation::admit`), and the locked body awaits the admitted set before `unused`, so an access that commits into the checkout makes the recheck retain it. Accesses that arrive after the removal registered still queue behind it through `exclusiveCheckout`. The admitted set is a snapshot taken under the lock; an access admitted later is blocked by `removing`, not by the snapshot. Covered by the "holds directory entry for a relative path into a checkout being removed" and "retains a checkout that an access admitted before removal entered" tests in `packages/experimental/worktree/tests/archive.spec.ts`.
