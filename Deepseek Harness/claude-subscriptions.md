# claude-subscriptions code notes

`contrib/claude-subscriptions/index.js:slot`: the id was the lowercased label with spaces replaced by hyphens, so the valid names `a b` and `a-b` produced the same id, route and ownership key. A space now becomes an underscore, which the label alphabet (letters, digits, space, hyphen) cannot contain, so the mapping is injective apart from letter case. `profiles` skips a later directory whose id was already taken (two directories that differ only by case on a case-sensitive file system). The PR was unmerged and unreleased, so no stored id needs migration.

`contrib/claude-subscriptions/index.js:checkAccount`: `claude auth status --json` can print a non-JSON message (old client, wrapper script, missing login shell). `JSON.parse` then threw a raw SyntaxError into the settings page. The parse is wrapped and reports one fixed sentence. Directory comparison (`sameDirectory`) is case-insensitive only on win32 and darwin, where the file systems are case-insensitive by default; on Linux two paths that differ by case are two directories. `identity` equals `accountKey` now because the key already covers email and organisation.

`contrib/claude-subscriptions/index.js:startLogin`: `env.SystemRoot` is absent from some service-launched Windows processes; the PowerShell path falls back to `SYSTEMROOT`, `windir`, then `C:\Windows` instead of throwing a TypeError from `join`. On Windows the login child is PowerShell waiting on a grandchild, so `killTree` runs `taskkill /T /F` besides `child.kill()`; a plain kill would leave the Claude CLI waiting for the browser.

`contrib/claude-subscriptions/index.js:apply` (`logins`): each pending login now has a timeout (`DSH_CLAUDE_LOGIN_TIMEOUT_MS`, default 300000, read at login start so tests can shorten it). Timeout, `error` and `close` all go through `finishLogin`, which clears the timer and removes the map entry once; before, an `error` event left the entry in the map and the profile looked pending forever. A timeout records its own message and the following `close` does not overwrite it (`timedOut`); the same holds for an `error` followed by `close` (the close handler only writes a generic error when none is set). The dispose effect kills every login child and clears the timers so a closed settings page or reload does not leave browser logins running.

`contrib/claude-subscriptions/index.js:apply` (`displaced`): the default profile always owns its account, so a managed profile that held the same account used to be rejected and locally signed out without a word. `reconcileOwnership` now records the displaced managed ids and `refresh` keeps a sentence naming them in the notice until the next add or login action starts.

`contrib/claude-subscriptions/ownership.js:accountKey`: the ownership key was an unsalted SHA-256 of the lowercased email, which anyone who can read `.ownership.json` can confirm against a guessed address. The key is now HMAC-SHA256 over the JSON of `[lowercased email, organisation id]` with a random per-install secret in `.ownership-secret` (mode 0600, created exclusively). Including the organisation id means one email in two organisations is two identities. `legacyAccountKey` still computes the old hash because `reconcileOwnership` migrates old registry entries: an owner entry whose key equals the row's legacy hash and whose owner id is this row is re-keyed to the new key; a rejected entry that carries the legacy hash is dropped and recomputed (the old hash cannot tell organisations apart, so the old verdict is not trusted). Entries of signed-out profiles are not migratable because the email is unknown; they were already dropped by the existing signed-out rule. The registry version is 2; version 1 is still read.

`contrib/claude-subscriptions/ownership.js:readOwnership`: a registry that does not parse, has the wrong shape or an unknown version used to throw, so every list failed until someone deleted the file. It now returns an empty state with `corrupt` set. `updateOwnership` copies the bad file to `.ownership.json.corrupt-<timestamp>` before the rewrite, so the evidence is kept and the next list works. Read-only callers (`auth.check`) never write a backup. Other I/O errors (permissions) still throw.

`contrib/claude-subscriptions/ownership.js:updateOwnership`: `observe()` runs `claude auth status` per profile and can take seconds; it ran inside the file lock (waitMs 40000), so a slow observation held other Harness processes. It now runs first, and the lock covers only read, reconcile and write. The registry directory and profile directories are created with mode 0o700 (ignored on Windows) because they hold Claude credentials.

`contrib/claude-subscriptions/client.js:AccountPage`: the pending poll doubled from 3 s up to 30 s and restarts at 3 s whenever pending turns false and true again (the effect re-runs). It stops entirely when no account is pending. Strings stay English: the repository client plugins register typed dictionaries through `ctx.locale.register`, and the dynamic-package browser docs do not describe a locale service for out-of-tree bundles. Whether a plain-JS bundle can inject it was not verified, so translation was not attempted and the README lists English-only as a limitation.

`contrib/claude-subscriptions/prepare-bridge.mjs:archive`: `DSH_CLAUDE_BRIDGE_TARBALL` reads the adapter tarball from a local file instead of fetching, and `DSH_CLAUDE_BRIDGE_SKIP=1` skips the build when `bridge/index.js` already exists, so `npm test` works offline. The SHA-512 digest check applies to both the downloaded and the local tarball.

`contrib/claude-subscriptions/index.js:fromBridge`: the plugin loads the adapter's CLI lookup, spend gate, session manager and tool bridge from the bundled `bridge/` instead of re-implementing them, so the managed profiles behave like the installed primary provider.

`contrib/claude-subscriptions/index.js:checkAccount` (account info fallback): migrated Claude Code profiles can lack the cached email and organisation in `auth status`; the same official client is asked for its account description without sending a prompt. That description carries an organisation name, not the id, so the id used in `accountKey` stays the one from `auth status` (empty when absent) and the key cannot change between the two code paths.

`contrib/claude-subscriptions/index.js:startLogin`: the user starts the login from the account page; Claude Code owns the browser redirect and its console fallback, so no OAuth code or token reaches the renderer.

`contrib/claude-subscriptions/index.js:signOutDuplicate`: the selected directory and identity are checked again immediately before `auth logout`, so a profile whose sign-in changed in between is not cleared.

`contrib/claude-subscriptions/ownership.js:reconcileOwnership`: the default profile owns its native route, existing assignments are kept, older profiles migrate first, and a previously rejected sign-in cannot promote itself.

`contrib/claude-subscriptions/prepare-bridge.mjs:digest`: build-time input only; the installed bundle contains the adapter and its license. The adapter reports the upstream version to its own SDK tool bridge, which is why the copied `package.json` keeps the upstream name and version.

`contrib/claude-subscriptions/index.js:killTree`: on Windows the login child is PowerShell waiting on a grandchild. `taskkill /T` walks the tree from the child's pid, so the child must still exist when taskkill runs; the previous code called `child.kill()` right after starting taskkill and the grandchild survived. `child.kill()` now runs in the taskkill callback, taskkill is addressed by its absolute System32 path (not found through PATH), and a taskkill failure is logged as a warning before the plain kill. `killTree` returns a promise so the dispose effect waits for it.

`contrib/claude-subscriptions/index.js:windowsSystemPath`: `'C:\Windows'` in a JS string is `C:Windows` because `\W` is not an escape, so the fallback needs `\`. The path is built with `path.win32.join` so the result does not depend on the host platform and a test can check it anywhere.

`contrib/claude-subscriptions/index.js:loginTimeoutMs`: a non-numeric, zero or negative `DSH_CLAUDE_LOGIN_TIMEOUT_MS` falls back to five minutes; a number is clamped to 1000 ms .. 2^31-1 ms because `setTimeout` treats larger values as 1 ms and a tiny value would kill a login before the browser opens.

`contrib/claude-subscriptions/ownership.js:reconcileOwnership`: a v1 rejected entry carries the legacy email hash and names its owner. It is dropped only when that owner's own entry was migrated in the same pass or the owner profile no longer exists. While the owner row is in error (status unreadable once) the entry stays, and the duplicate is exempt from the "key changed" cleanup for its legacy key, so a transient failure cannot promote the duplicate to owner and then sign the real owner out. Migration therefore runs as two passes: owners first, then rejected entries.

`contrib/claude-subscriptions/ownership.js:secretFor`: the secret is written to a unique temp file and hard-linked into place, so a reader sees either no file or a complete 64-hex secret and a crash cannot leave a half-written secret. A file that exists but is not 64 hex digits (left by an earlier crash or an older build) is stale and replaced by rename. When another process wins the link (EEXIST) its secret is read back.

`contrib/claude-subscriptions/ownership.js:updateOwnership` (`displaced`): the ids of profiles displaced by the default profile are stored in the registry (`displaced`, optional, version 2) and kept only while the profile still exists and is still rejected in favour of `main`. The notice is rebuilt from this list on every refresh, so it survives a Harness restart and disappears once the profile is signed in with another account or removed.

`contrib/claude-subscriptions/index.js:apply` (`notice`): the one-shot notice (duplicate sign-in, failed local sign-out) is cleared after a response that included it has been delivered; while a cause persists (a failed sign-out retried by every refresh) the refresh sets it again. Keeping it until the next login start left stale text on the page, and clearing it on the next refresh would lose it, because the refresh triggered by the login child's exit runs before the client's next poll.

`contrib/claude-subscriptions/client.js:AccountPage`: the poll effect depends on the sorted ids of the pending accounts, not on a boolean, so starting a second sign-in while one is pending restarts the delay at 3 s instead of continuing at the capped delay.

`contrib/claude-subscriptions/ownership.js:reconcileOwnership` (displaced): a displaced notice is kept only while the registry still rejects the profile in favour of `main` and `main` still owns that account key. A rejected entry whose key has no owner is dropped at the end of every pass. This is how the notice clears when the default profile moves to another account or signs out: its owner entry is deleted by the existing mismatch rule, the rejected entry then has no owner, and the list is empty. The same cleanup frees a duplicate whose owner signed out; before, it stayed rejected and hidden.

`contrib/claude-subscriptions/ownership.js:secretFor` (fallback): where hard links are unavailable (EPERM on some network or FAT volumes, ENOSYS, EXDEV) the secret is copied into place with an exclusive `wx` write, and EEXIST there means another process won and its secret is read back. That path is not atomic: a reader can see a short file and treat it as stale. Replacing a pre-existing invalid secret is also a rename race between two first-time processes; both are accepted and listed in the README, because the window only exists on first use.

`contrib/claude-subscriptions/index.js:apply` (`say`, `noticeSeq`): the one-shot notice is now cleared by an acknowledgement, not by being sent. Each new notice text bumps `noticeSeq` and the response carries it as `noticeId`. The client sends `ackNotice` with the id of the last notice it actually displayed; the server clears the notice only when that equals the current id. The previous clear-on-send lost the notice whenever the client dropped a response that was superseded by a newer call. A re-set of the same text (a failed sign-out retried by every refresh) does not bump the id.

`contrib/claude-subscriptions/client.js:AccountPage` (`acknowledged`): `acknowledged` is updated only after `setNotice` ran for an applied (not stale) response with a non-empty notice, so a dropped response is re-delivered by the next call.

`contrib/claude-subscriptions/index.js:apply` (legacy clients): a browser tab that still runs the previous client sends `includeNotice` without `ackNotice` and would never clear the notice now that clearing needs an acknowledgement. A request with `includeNotice` and an undefined `ackNotice` is treated as a legacy client: the notice is cleared after that response, as before. The current client always sends a number (0 before it has shown anything), so the two cases cannot be confused.

`contrib/claude-subscriptions/index.js:apply` (`noticeSeq`): the sequence restarted at 0 on every plugin load, so an id a client acknowledged before a reload could equal the id of an unseen notice created after it. It now starts from `Date.now() * 1000` plus a random offset below 1000, which stays below 2^53 and cannot repeat across loads (the sequence would have to advance 1000 times within one millisecond). Zero stays reserved for "nothing shown yet".

`contrib/claude-subscriptions/ownership.js:secretFor` (EEXIST): two tests cover another process winning the creation race, once through `linkSync` throwing EEXIST and once through a failed link followed by the `wx` fallback write finding the file; both must end up using the winner's secret.

`contrib/claude-subscriptions/index.js:say`: the notice is one global value shared by every open settings tab, and a repeat of identical text while it is still set does not bump the id, so a second tab can miss a message the first tab already acknowledged and an identical repeat is not announced again. Accepted and listed in the README.
