# ui-primitives code notes

## packages/client/ui-primitives/src/markdown/render.tsx:MarkdownImage

`packages/client/ui-primitives/src/markdown/render.tsx:MarkdownImage`: Finding 184. An authored absolute HTTP(S) image destination used to become an `<img>` at once, so an untrusted Markdown document could make the viewer's browser contact an attacker host with a unique URL (address and view disclosure). `referrerPolicy: no-referrer` hides the referrer only. Remote authored images now render a click-to-load button (label: alt text, else the URL host; `title` is the URL) and the request happens only after that click, one image at a time. Consent is component state, so a remount asks again. Images inside a link cannot hold a nested button, so they stay inert alt text and the link remains the way to open the target. Not covered by the gate: images produced by the owner-supplied `pathImages` vocabulary and `fileImages.resolve` (owner-vouched URLs, including Host file routes), and local attachment previews. Residual limit: after the click the host sees the viewer's address; the gate is consent, not anonymisation (no proxy).

## packages/client/ui-primitives/src/settings-form/form-model.ts:SettingsFormModel::save

`packages/client/ui-primitives/src/settings-form/form-model.ts:SettingsFormModel::save`: Finding 398 and 400. Save used to write the settings operations first and the credential writes after. Two defects followed. A provider selection could take effect before its staged key was written, so a refused key write left the new provider active without the key (finding 400). And `staged.clear()` after a landed save dropped every draft, including edits typed while the save was in flight, so the control reverted to the older accepted value without saving the newer edit (finding 398). Decision: credential writes run first, and the settings operations are sent only when every credential write landed. Each credential write still runs even after an earlier refusal, so every refused key is reported. A credential written before a refused settings operation stays written; its draft remains staged, so a retry rewrites the same value, which is idempotent. Default chosen: a credential is saved and confirmed before any setting that depends on it. No other card uses credential writers, so the order change affects only the web search page.

## packages/client/ui-primitives/src/settings-form/form-model.ts:SettingsFormModel::settle

`packages/client/ui-primitives/src/settings-form/form-model.ts:SettingsFormModel::settle`: Finding 398. Clears only the staged entries whose edit object is still the one the save sent, so a same-field or different-field edit made during the save survives. Edit objects are compared by identity: every stage call creates a new object, so an edit made during the save is never mistaken for the sent one. When edits survive, the baseline is re-captured from the current scope snapshot, because the write fence must name the revision the save just landed. A landed write updates the scope synchronously for the latest request, so that snapshot is the accepted revision. Known limit: a superseded write leaves the snapshot on the older revision, so the next save may be refused until the form is discarded; this matches the existing refusal behaviour for a stale baseline.

`packages/client/ui-primitives/src/WebBlock.tsx:WebFetchBlock` (finding 343): a fetch card whose status was not reported shows the localized `statusNotReported` label in place of the `HTTP <n>` text, so a successful fetch of unknown status is visible as such and never reads as HTTP 200. `finalUrlUnreported` adds `finalUrlNotReported` beside it and the link then points at the requested URL. Both labels are required in `WebBlockLabels`, so every dictionary carries them (`web.statusNotReported`, `web.finalUrlNotReported`).
